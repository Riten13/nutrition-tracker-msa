# Food Database Microservice — Detailed Project Flow

---

## Overview

This microservice follows a strict **3-layer architecture**:

```
Client (Postman / Other Services)
          │  HTTP Request
          ▼
    [ Controller ]      ← Receives HTTP, sends HTTP
          │  Java method call
          ▼
    [   Service  ]      ← Business logic, mapping
          │  Java method call
          ▼
    [ Repository ]      ← Talks to MongoDB
          │  MongoDB query
          ▼
      [ MongoDB ]       ← Stores / retrieves data
          │  MongoDB result
          ▲
    [ Repository ]
          │
    [   Service  ]      ← Maps model → DTO
          │
    [ Controller ]      ← Sends HTTP response
          │  HTTP Response
          ▼
Client (Postman / Other Services)
```

---

## Layer-by-Layer Explanation

### Layer 1 — Controller (`FoodController.java`)

**What it does:**
- Listens for incoming HTTP requests on `/api/foods`
- Reads data from the request (path variables, query params, request body)
- Calls the correct method in `FoodService`
- Returns an HTTP response with the right status code (`200`, `201`, `204`, `404`)

**What it does NOT do:**
- Does NOT talk to MongoDB directly
- Does NOT contain any business logic
- Does NOT do any data transformation

```
Incoming: HTTP Request (JSON body, URL params)
Outgoing: HTTP Response (JSON body, status code)
```

---

### Layer 2 — Service (`FoodService.java`)

**What it does:**
- Contains all the business logic
- Decides which repository method to call
- Validates whether a food exists before updating or deleting
- Converts `FoodRequest` DTO → `Food` model (before saving)
- Converts `Food` model → `FoodResponse` DTO (before returning)
- Throws `FoodNotFoundException` if food is not found

**What it does NOT do:**
- Does NOT handle HTTP directly
- Does NOT write MongoDB queries

```
Incoming: DTOs (FoodRequest / NutritionDto)
Outgoing: DTOs (FoodResponse / NutritionDto)
```

---

### Layer 3 — Repository (`FoodRepository.java`)

**What it does:**
- Interfaces directly with MongoDB
- Spring Data MongoDB **auto-generates** all queries from method names
- No SQL or MongoDB query code needed — Spring handles it all

**Methods available (auto-generated by Spring):**

| Method | What it does |
|--------|-------------|
| `findAll()` | Returns all food documents |
| `findById(id)` | Returns one food by `_id` |
| `save(food)` | Inserts or updates a food document |
| `deleteById(id)` | Deletes a food document by `_id` |
| `existsById(id)` | Returns true if food exists |
| `findByNameContainingIgnoreCase(name)` | Case-insensitive name search |
| `findByCategoryIgnoreCase(category)` | Case-insensitive category filter |

```
Incoming: Java Food model objects
Outgoing: Java Food model objects (fetched from MongoDB)
```

---

## DTO vs Model — Why Both?

| | Model (`Food`, `Nutrition`) | DTO (`FoodRequest`, `FoodResponse`, `NutritionDto`) |
|---|---|---|
| **Purpose** | Represents the MongoDB document | Represents what the API sends/receives |
| **Used by** | Repository layer | Controller and Service layers |
| **Has `@Id`?** | Yes (`Food`) | No |
| **Has `@Document`?** | Yes (`Food`) | No |
| **Exposed to client?** | Never directly | Always |

The **Service layer is the only place** where the conversion between model and DTO happens.

## Complete Request Flows

---

### Flow 1 — POST `/api/foods` (Add Food)

```
1. Client sends POST /api/foods with JSON body

2. FoodController.addFood(@RequestBody FoodRequest request)
   - Receives the JSON body as a FoodRequest DTO
   - Calls foodService.addFood(request)

3. FoodService.addFood(FoodRequest request)
   - Converts FoodRequest → Food model  (toFood method)
   - Converts NutritionDto → Nutrition  (toNutrition method)
   - Calls foodRepository.save(food)

4. FoodRepository.save(food)
   - Spring Data inserts the document into MongoDB "foods" collection
   - MongoDB auto-generates the _id
   - Returns the saved Food object with the generated id

5. FoodService
   - Converts saved Food model → FoodResponse DTO  (toFoodResponse method)
   - Returns FoodResponse to Controller

6. FoodController
   - Returns HTTP 201 Created with FoodResponse as JSON body
```

---

### Flow 2 — GET `/api/foods` (Get All / Search / Filter)

```
1. Client sends GET /api/foods
   OR GET /api/foods?name=chicken
   OR GET /api/foods?category=meat

2. FoodController.getFoods(@RequestParam name, @RequestParam category)
   - Reads optional query parameters
   - Calls foodService.getFoods(name, category)

3. FoodService.getFoods(name, category)
   - If name is provided  → calls foodRepository.findByNameContainingIgnoreCase(name)
   - If category provided → calls foodRepository.findByCategoryIgnoreCase(category)
   - If neither provided  → calls foodRepository.findAll()

4. FoodRepository
   - Runs the appropriate MongoDB query
   - Returns List<Food>

5. FoodService
   - Converts each Food → FoodResponse using Stream + map
   - Returns List<FoodResponse>

6. FoodController
   - Returns HTTP 200 OK with List<FoodResponse> as JSON array
```

---

### Flow 3 — GET `/api/foods/{foodId}` (Get One Food)

```
1. Client sends GET /api/foods/66f1a2b3c4d5e6f7a8b9c0d1

2. FoodController.getFoodById(@PathVariable String foodId)
   - Extracts foodId from the URL
   - Calls foodService.getFoodById(foodId)

3. FoodService.getFoodById(foodId)
   - Calls foodRepository.findById(foodId)
   - If not found → throws FoodNotFoundException("66f1...")

4a. If found:
   - FoodRepository returns Optional<Food> with value
   - Service converts Food → FoodResponse
   - Controller returns HTTP 200 OK with FoodResponse

4b. If NOT found:
   - FoodNotFoundException is thrown
   - GlobalExceptionHandler catches it
   - Returns HTTP 404 Not Found with error JSON
```

---

### Flow 4 — PUT `/api/foods/{foodId}` (Update Food)

```
1. Client sends PUT /api/foods/66f1a2b3c4d5e6f7a8b9c0d1 with JSON body

2. FoodController.updateFood(@PathVariable foodId, @RequestBody FoodRequest request)
   - Calls foodService.updateFood(foodId, request)

3. FoodService.updateFood(foodId, request)
   - Calls foodRepository.findById(foodId)
   - If not found → throws FoodNotFoundException (returns 404)
   - If found → updates all fields on the existing Food object:
       existingFood.setName(request.getName())
       existingFood.setCategory(request.getCategory())
       existingFood.setDescription(request.getDescription())
       existingFood.setNutrition(toNutrition(request.getNutrition()))
   - Calls foodRepository.save(existingFood)
     (save() with an existing _id = UPDATE, not insert)

4. FoodRepository
   - Updates the document in MongoDB (same _id, new field values)
   - Returns updated Food object

5. FoodService
   - Converts updated Food → FoodResponse
   - Returns FoodResponse

6. FoodController
   - Returns HTTP 200 OK with updated FoodResponse
```

---

### Flow 5 — DELETE `/api/foods/{foodId}` (Delete Food)

```
1. Client sends DELETE /api/foods/66f1a2b3c4d5e6f7a8b9c0d1

2. FoodController.deleteFood(@PathVariable String foodId)
   - Calls foodService.deleteFood(foodId)

3. FoodService.deleteFood(foodId)
   - Calls foodRepository.existsById(foodId)
   - If NOT found → throws FoodNotFoundException (returns 404)
   - If found → calls foodRepository.deleteById(foodId)

4. FoodRepository
   - Deletes the document from MongoDB
   - Returns void

5. FoodController
   - Returns HTTP 204 No Content (empty body)
```

---

### Flow 6 — GET `/api/foods/{foodId}/nutrition` (Get Nutrition)

```
1. Client sends GET /api/foods/66f1a2b3c4d5e6f7a8b9c0d1/nutrition

2. FoodController.getNutrition(@PathVariable String foodId)
   - Calls foodService.getNutrition(foodId)

3. FoodService.getNutrition(foodId)
   - Calls foodRepository.findById(foodId)
   - If not found → throws FoodNotFoundException (returns 404)
   - If found → extracts food.getNutrition()
   - Converts Nutrition model → NutritionDto  (toNutritionDto method)
   - Returns NutritionDto

4. FoodController
   - Returns HTTP 200 OK with NutritionDto as JSON body
   - (Only the nutrition object — NOT the full food)
```

## Exception Handling Flow

```
Any layer throws FoodNotFoundException
          │
          ▼
GlobalExceptionHandler.handleFoodNotFound()
  - Builds an error map with: timestamp, status, error, message
  - Returns HTTP 404 Not Found with JSON error body

Any layer throws any other Exception
          │
          ▼
GlobalExceptionHandler.handleGenericException()
  - Returns HTTP 500 Internal Server Error with JSON error body
```

This means **controllers never crash** — every exception is caught and returned
as a clean JSON response to the client.

```
    │

  description: "..."
  nutrition: Nutrition {
    servingSize: 100,

    calories: 165,

  }

    │
    ▼ foodRepository.save(food)
MongoDB document in "foods" collection:

  "_id": "66f1a2b3c4d5e6f7a8b9c0d1",   ← auto-generated by MongoDB
  "name": "Chicken Breast",
  "category": "Meat",
  "description": "Skinless boneless chicken breast",
  "nutrition": {                          ← embedded sub-document
    "servingSize": 100,
    "servingUnit": "g",
    "calories": 165,
    "protein": 31,
    "carbs": 0,
    "fat": 3.6,
    "fiber": 0
  }
}
    │
    ▼ toFoodResponse() in FoodService
FoodResponse (returned to client)
```

## File Responsibility Summary

| File | Responsibility |
|------|---------------|
| `FoodDatabaseApplication.java` | Starts the Spring Boot app |
| `FoodController.java` | Maps HTTP endpoints to service methods |
| `FoodService.java` | Business logic + model/DTO conversion |
| `FoodRepository.java` | MongoDB queries via Spring Data |
| `Food.java` | MongoDB document model (`@Document`) |
| `Nutrition.java` | Embedded nutrition sub-document |
| `FoodRequest.java` | DTO — what client sends (POST/PUT body) |
| `FoodResponse.java` | DTO — what API returns to client |
| `NutritionDto.java` | DTO — nutrition data in API |
| `FoodNotFoundException.java` | Custom exception for missing food (404) |
| `GlobalExceptionHandler.java` | Converts exceptions into JSON responses |
| `application.yml` | MongoDB URI, server port, logging config |
| `pom.xml` | Dependencies: Spring Boot, MongoDB, Lombok |
